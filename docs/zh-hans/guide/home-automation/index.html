概览

家庭自动化能做什么

家庭自动化让 Projector Pilot 从您手中的遥控器，变成整个家都能看到的设备。它会公开投影机正在做什么，包括电源、信号源、色彩模式、画面数值和灯泡使用时长，并为您的智能家居提供应用能更改的每一项内容的控制。

  • 它发布状态。投影机会以 Home Assistant 传感器、Hubitat 设备，或发送到您 Webhook 的 JSON 数据形式出现，携带与应用中显示的相同读数。
  • 它发布控制。您保存的每个场景，以及电源、每个信号源、每个色彩模式和每个镜头记忆，都会变成自动化或语音助手可以运行的内容。
  • 它无需服务器。脚本设置好后，Home Assistant 会直接向投影机的 IP 地址发送命令。您的手机不需要在网络中，也不会经过任何云账号。
家庭自动化是付费附加组件。它是一次性购买，与 Projector Pilot Pro 分开，购买捆绑包可以同时获得两者并享受优惠。无需订阅，无需账号，无需云端。请查看价格。

三种接入方式，一个中心

“设置” › “家庭自动化”就是中心。选择您使用的平台：Home Assistant、Hubitat 或 Webhook，并在那里完成设置。您可以同时接入多个平台，它们彼此独立。

Home Assistant

设置 Home Assistant

在应用中登录，将投影机发布为传感器，把一段代码块粘贴到您的配置中，然后同步。从此以后，Home Assistant 会自行驱动投影机。

  1. 打开设置 › 家庭自动化 › Home Assistant。
  2. 输入您的 Home Assistant 地址（例如 http://homeassistant.local:8123 或它的 IP 地址），然后轻点登录。这是针对您自己实例的浏览器登录，无需粘贴令牌。使用您平时登录 Home Assistant 的账号即可，包括双重验证。
  3. 应用会将投影机发布为一个传感器，实体类似 sensor.projector_pilot_epson_qb1000b_qb1000w，携带电源、信号源、色彩模式、画面数值和灯泡使用时长。
  4. 开启发送投影机状态，这样应用打开期间，这些读数一有变化就会在 Home Assistant 中更新；再开启同步高级控件，发布画面模式、信号源、镜头记忆和电源对应的脚本。
  5. 把那一段 shell_command 代码块（见下文）粘贴到您的 configuration.yaml，重启 Home Assistant，然后轻点与 HA 同步。

shell_command 代码块

这就是无需服务器的全部诀窍。应用会写入一条供 Home Assistant 运行的命令，用来与投影机的 Web Control 通信，而它同步的每个脚本都用不同的动作调用这条命令。在应用中轻点复制代码块，然后粘贴到 configuration.yaml。下面的示例仅作说明，应用会填入您投影机自己的地址和命令名称：

shell_command:
  projector_pilot_epson: >-
    curl -s --max-time 5 --digest -u 'EPSONWEB:'
    -H "X-Requested-With: XMLHttpRequest"
    -H "Referer: http://192.168.1.50/cgi-bin/webconf"
    "http://192.168.1.50/cgi-bin/directsend?{{ verb }}={{ value | urlencode }}"

仅为示例。应用会使用投影机的真实 IP 地址，以及由其序列号派生的名称，为您生成专属代码块。

为什么无需服务器。那个 curl 运行在 Home Assistant 主机上，而不是您的手机上。Home Assistant 通过 Web Control 直接连接投影机的 IP 地址，所以无论应用是否打开，也无论您的手机是否在家，自动化都能触发。EPSONWEB 摘要用户就是 Web Control 登录账号；应用会使用已为该投影机保存的 Web Control 密码。

测试连接、同步和清理

  • 测试连接会检查应用能否连上您的 Home Assistant，以及粘贴的 shell_command 是否确实存在，让您在构建任何内容之前就能发现拼写错误。
  • 与 HA 同步会为您的场景和控件写入或更新脚本，并直接在 Home Assistant 中构建一个现成的 Projector Pilot 仪表盘。每当您添加场景或更改控件时都可以再次运行，它会就地更新，而不会堆积重复项。
  • 移除孤立脚本会找出应用写入、但已没有对应场景或控件的脚本，例如在您删除场景之后，列出它将移除的确切内容，并先征求您的同意。在您确认之前不会删除任何内容。它只会处理 Projector Pilot 创建的脚本，您 Home Assistant 中的其他内容不会受到影响；如果 Home Assistant 不提供脚本列表，则不会移除任何内容。
设置清单

应用会告诉您哪些已完成，哪些还缺少

Home Assistant 界面带有设置清单和您的 Home Assistant 已具备的内容面板，让您不必猜测还剩哪一步。每一行都会说明该项是已完成、缺失还是无法确定，并告诉您下一步该做什么。

  • 已连接到 Home Assistant：已登录并有响应。如果 Home Assistant 没有响应，该行会提示您检查地址，并确认手机在同一网络中。
  • 投影机已添加到 Home Assistant：Home Assistant 是否已经有这台投影机。如果没有，该行会引导您添加 PJLink 集成，而添加集成的步骤会显示 Home Assistant 要求填写的 PJLink 主机和端口。
  • 读数传感器已注册：承载投影机读数的传感器。它会在应用第一次读取投影机时注册，如果有因素阻止注册，该行会提供立即注册或开启选项。
  • 您的 Home Assistant 已具备的内容：HACS（社区商店）、Epson Projector Link 集成、PJLink 集成，以及 configuration.yaml 中的 Projector Pilot 命令。每一项会显示已找到、未安装或无法确定，并在需要时提供“安装方法”和“在 HACS 中打开”按钮。
“重新检查”会告诉您它找到了什么。修复某项问题后，轻点重新检查，应用会重新读取您的 Home Assistant 并报告结果，而不是让您猜测是否生效。无法检查的行会显示无法确定，绝不会给出猜测的“是”或“否”。
与您已有的设置协同工作

支持核心 PJLink 集成，有更丰富的卡片时则更出色

Projector Pilot 会了解您的 Home Assistant 安装了什么，并据此构建。它支持 Home Assistant 自带的核心 PJLink 集成，所以您已经在那里添加的 PJLink 投影机会得到一流的支持。

  • 优先使用内置卡片。如果您没有社区卡片，同步会使用 Home Assistant 的内置卡片构建仪表盘，并在完成后告诉您。开箱即用。
  • 安装了 HACS 卡片时自动升级。应用会检查已安装哪些社区卡片（Mushroom、button-card、card-mod、apexcharts-card），并在您已安装的情况下，把每张卡片升级为更丰富的版本。如果您想要完整的绿色玻璃外观，手工打造仪表盘指南会带您更进一步。
  • 场景和控件需要粘贴一次。如果 Home Assistant 中还没有向投影机发送命令的指令，仪表盘依然会带着实时读数构建出来，同时会出现完成设置卡片引导您：轻点复制代码块，粘贴到 configuration.yaml，重启 Home Assistant，然后再次轻点同步。
  • 什么都没安装？手动粘贴。即使 Home Assistant 中什么都没有安装，您仍然可以从应用中复制全部内容并自行粘贴。
  • 密码会明确标出。您粘贴的命令代码块会在包含投影机密码时明确说明，让您在分享或存储之前就心中有数。
投影机关机期间

保持不变的读数

待机中的投影机上报的信息很少，所以仪表盘通常会变成空白。可选的最近已知传感器会在投影机关机期间，把投影机最近的读数，例如信号源、灯泡或激光使用时间，保留在 Home Assistant 中。

  • 这又是一个可选代码块：把它粘贴到 configuration.yaml 的末尾（或者只把它的几行添加到现有的 template: 部分下），然后重启 Home Assistant。应用提供检查是否存在按钮，会告诉您 Home Assistant 中是否已有它。
  • 现在关机会以off的状态传到 Home Assistant，所以仪表盘和您的自动化在投影机关机时就会看到它处于关闭状态。
场景即脚本

每个场景都会变成一个 Home Assistant 脚本

同步之后，您的场景不会被困在应用里。每个场景，以及您的投影机实际具备的电源、每个信号源、每个色彩模式和每个镜头记忆，都会被写成一个 Home Assistant 脚本。

  • 自动化可以运行它们。“日落时，如果TV 开了，就运行观影之夜”，一旦场景成为脚本，这就是一个普通的 Home Assistant 自动化。
  • 语音助手可以运行它们。把脚本开放给您的助手，说“打开观影之夜”，就会一并设置信号源、画面模式和镜头记忆。
  • 只会出现真实的控件。应用只为投影机上报的每个信号源、色彩模式和镜头记忆写入脚本，而不是它猜测出来的通用列表。
  • 取消同步只会移除应用写入的内容。关闭同步，或使用“移除孤立脚本”（它会列出内容并先征求您的同意），Projector Pilot 只会删除它自己创建的脚本，不会动其他任何内容。
脚本的命名方式让重命名只会更新同一个脚本。脚本名称由投影机和控件派生，所以重命名场景后重新同步，会更新现有脚本，而不会分出第二个副本。
仪表盘

同步为您构建仪表盘

您不需要手工搭建 Lovelace 视图，现在也不再需要粘贴了。当您轻点与 HA 同步时，应用会通过 Home Assistant 自己的 API，直接在 Home Assistant 中构建完整的 Projector Pilot 仪表盘：包含投影机的实时状态，以及它同步的每个场景和控件对应的按钮。它会以 Projector Pilot 的名称出现在您的 Home Assistant 侧边栏中，打开即可，一切就绪。

  1. 在应用中登录 Home Assistant。
  2. 把应用的复制代码块粘贴到 configuration.yaml 一次，并重启 Home Assistant（这是唯一的手动步骤，因为 Home Assistant 不允许应用远程添加该命令）。
  3. 轻点与 HA 同步。仪表盘会为您构建完成，并以 Projector Pilot 的名称出现在侧边栏中。
更想自己粘贴？Home Assistant 界面上仍然保留着复制仪表盘。轻点它，然后在 Home Assistant 中进入设置 › 仪表盘 › 添加仪表盘，创建一个空仪表盘，打开它的三点菜单 › 编辑仪表盘 › 三点菜单 › 原始配置编辑器，然后粘贴复制的 YAML。

无论是为您构建的，还是您自己粘贴的，仪表盘都是一样的：一张状态卡片，加上每个控件对应的按钮（示意片段）：

views:
  - title: Projector
    cards:
      - type: entity
        entity: sensor.projector_pilot_epson_qb1000b_qb1000w
        name: Projector
      - type: button
        name: Power On
        tap_action:
          action: perform-action
          perform_action: script.turn_on
          target:
            entity_id: script.projector_pilot_power_on
      - type: button
        name: Movie Night
        tap_action:
          action: perform-action
          perform_action: script.turn_on
          target:
            entity_id: script.projector_pilot_scene_movie_night

仅为示例。您的仪表盘会带有您投影机的真实实体和您自己的场景。

不限机型。仪表盘根据您的投影机自身的功能来构建：实体、画面数值、信号源、色彩模式、镜头记忆和场景，都是它实际上报的内容。这里的截图来自 QB1000，您的机型可能显示不同的信号源、控件和读数。如果想要像图中那样完整的绿色玻璃面板，请按照分步仪表盘指南操作，或下载完整视图并修改两个字符串。
想要更丰富的面板墙？同样的脚本可以驱动您喜欢的任何卡片。如果您用过 AVR Maestro，做法完全一样：基于同一个传感器和同步脚本，构建点亮的信号源与模式图块、实时标题和历史记录。
Hubitat

设置 Hubitat

在 Hubitat 上，Projector Pilot 会通过 Maker API 把投影机镜像到您 Hub 中的一台设备上，这样 Rule Machine 就能读取电源、静音和信号源并据此执行操作。

  1. 在 Hubitat 中，启用 Maker API 应用，记下它的访问 URL 和令牌，并选择要开放哪些设备。
  2. 在 Projector Pilot 中，打开设置 › 家庭自动化 › Hubitat，输入您 Hub 的 Maker API 信息。
  3. 选择代表投影机的设备。应用会推荐最可能的那个，您可以选择它，也可以选择自己的设备。
  4. 应用会把电源、静音和信号源镜像到该设备，并且只发送该设备接受的命令。
  5. 像对待其他设备一样，针对该设备构建 Rule Machine 规则，投影机的状态会驱动这些规则。
只发送设备接受的内容。只有当所选设备支持相应命令时，应用才会把投影机的值发送到 Hubitat，所以绝不会推送设备会拒绝的内容。
Webhook

设置 Webhook

Webhook 是万能方案。当投影机开机、关机、切换信号源或调用场景时，应用会向您指定的 URL 发送请求，可以是 Home Assistant Webhook、Node-RED、IFTTT，或任何接受 JSON 的服务。

  1. 打开设置 › 家庭自动化 › Webhook。
  2. 输入要发送请求的 URL。Home Assistant Webhook 的形式类似 http://homeassistant.local:8123/api/webhook/your-id。
  3. 选择哪些事件会触发 Webhook：开机、关机、信号源切换、场景调用，也可以选择只针对特定的信号源或场景进行筛选。
  4. 如果接收服务需要特定格式，可以选择设置自定义负载内容；否则应用会发送默认的 JSON。
  5. 保存。此后，应用会在每个匹配的事件发生时发送请求。

默认的负载内容是纯 JSON：包含事件、投影机，以及发生变化的值：

{
  "event": "scene_recalled",
  "projector": "Epson QB1000B/QB1000W",
  "scene": "Movie Night",
  "power": "on",
  "input": "HDMI1",
  "color_mode": "Cinema",
  "timestamp": "2026-09-23T20:14:07Z"
}

示例负载内容。信号源切换或电源事件会携带与之相关的字段。

重新关联可一次解决所有问题。如果您把 Home Assistant 重新关联到新的地址，应用会一次性更新所有指向它的 Webhook，所以实例迁移后，您不必逐个手动修改。

故障排除

登录后又跳回登录页面

请确认您输入的地址就是您实际访问 Home Assistant 所用的地址，包括端口（通常是 :8123）。登录是针对您自己实例的真实浏览器登录，所以您的用户名、密码和双重验证码都适用。在手机上，无论应用内浏览器是否把结果交还，还是本地回调先返回，登录都能完成；如果仍然卡住，请关闭该面板，再次轻点登录。

Home Assistant 中没有出现投影机传感器

只有在应用打开且发送投影机状态开启时，传感器才会发布，所以请打开应用并确认该开关。然后在 Home Assistant 中检查开发者工具 › 状态，并筛选 projector_pilot。待机中的投影机发布的信息很少，唤醒它，读数就会补全。

同步的脚本缺失

脚本由与 HA 同步写入，它要求 shell_command 代码块已粘贴到 configuration.yaml 并且 Home Assistant 已重启一次。请先运行测试连接，它会告诉您代码块是否存在。然后再次同步。如果失效的旧脚本让列表杂乱，请使用移除孤立脚本。

手机不在身边时，脚本在应用中能运行，在 Home Assistant 中却不行

这正是 shell_command 代码块的意义所在：它让 Home Assistant 能自行连接投影机的 IP 地址。如果它只有在应用打开时才能工作，很可能是代码块没有粘贴，或粘贴后没有重启 Home Assistant。请通过测试连接确认，重启 Home Assistant，然后同步。

常见问题

快速解答

手机必须一直在网络中，Home Assistant 自动化才能运行吗？

不需要。只要把那一段 shell_command 代码块粘贴到 Home Assistant 并同步，Home Assistant 就会直接向投影机的 IP 地址发送命令。Projector Pilot 只是设置工具；之后，无论您的手机在不在家，Home Assistant 都会自行与投影机通信。

投影机在 Home Assistant 中如何显示？

显示为一个传感器，例如 sensor.projector_pilot_epson_qb1000b_qb1000w，携带电源、信号源、色彩模式、画面数值和灯泡使用时长，并在应用打开期间随变化而更新。开启“同步高级控件”后，应用还会为每个场景，以及您的投影机具备的电源、每个信号源、每个色彩模式和每个镜头记忆，各写入一个 Home Assistant 脚本。
